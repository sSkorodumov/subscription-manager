# Менеджер Обязательств и Подписок (Billing Service)

Микросервис на Java 21 / Spring Boot 3.4.2 для автоматического учёта регулярных подписок, прогнозирования расходов и биллинга.

## 1. Как запустить проект (в один клик)
Проект полностью контейнеризирован. База данных PostgreSQL и само Java-приложение собираются и связываются автоматически. Миграции Flyway накатятся при старте.

Выполните команду в корневом каталоге проекта:
```bash
docker compose up --build
```
После успешного запуска интерактивная документация API (Swagger UI) будет доступна по адресу: `http://localhost:8080/docs`

## 2. Как запустить тесты
Интеграционные тесты изолированы от внешней СУБД и используют встроенную базу данных H2 в памяти. Для запуска тестов выполните:
```bash
mvn test
```

## 3. Обоснование бизнес-логики Lazy Expiry
Правило "Ленивого истечения" (Lazy Expiry) автоматически переводит просроченные обязательства (`next_payment_date < today`) в статус `EXPIRED` исключительно для **разовых** платежей (`recurrence = null`).

Для рекуррентных подписок статус умышленно остаётся `ACTIVE`. Это связано с тем, что в реальном мире, если пользователь забыл нажать кнопку «Оплачено» в приложении, сама подписка (например, Netflix) не аннулируется автоматически — поставщик услуги всё равно попытается списать деньги. Система сохраняет статус активным, чтобы Telegram-бот и фронтенд продолжали слать алерты о необходимости оплаты и предупреждать о списании.

## 4. Обработка граничных случаев с датами (Сдвиг рекуррентности)
Для предотвращения накопления смещения дат (например, когда пользователь оплачивает подписку на 5 дней позже срока), сдвиг следующего платежа считается строго от текущего `next_payment_date`, а не от фактического дня оплаты.

При расчёте используется поле `originalSubscriptionStartDay`. Если подписка была оформлена 31 января, то при сдвиге на 1 месяц на короткий февраль система выберет максимальный доступный день текущего месяца (`Math.min(31, 28 или 29 в високосный год)`), выставив `28` или `29 февраля`. При фиксации следующей оплаты в феврале, алгоритм вернёт дату следующего платежа на исходное число — `31 марта`, не теряя расчётные дни биллинга.

## 5. Компромиссы и точки роста (Что можно сделать иначе)
1. **Связность слоев (Вызов HTTP-исключений из сервиса)**: В целях ускорения разработки бизнес-ошибки (например, 404 при отсутствии записи или 422 при неверном статусе) выбрасываются напрямую из сервисного слоя через `ResponseStatusException`. В промышленной Clean Architecture это считается компромиссом, так как сервис привязывается к веб-специфике. Более правильный подход — выбрасывать чистые доменные Java-исключения бизнес-логики, а их маппинг в HTTP-статусы вынести на уровень контроллеров с помощью глобального перехватчика `@RestControllerAdvice`.
2. **Динамические SQL-фильтры**: В методе получения списков используется конструкция `if-else` для комбинаций параметров. При добавлении новых фильтров код станет перегруженным. Стоит заменить её на `Spring Data Specification` или `QueryDSL`.
3. **Обработка SSE-потоков**: Рассылка SSE-событий сейчас вызывается напрямую из контроллера. Для повышения отказоустойчивости при высоких нагрузках рассылку лучше перевести на асинхронные события Спринга (`ApplicationEventPublisher`) с аннотацией `@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)`.
4. **Логирование**: Системные выводы заменены стандартным выводом Spring Boot. Стоит внедрить гибкое структурированное логирование через SLF4J/Logback.

## 6. Примеры запросов (curl)

### Создание обязательства/подписки:
```bash
curl -X POST http://localhost:8080/obligations \
     -H "Content-Type: application/json" \
     -d "{\"title\":\"Netflix\",\"amount\":14.89,\"currency\":\"USD\",\"category\":\"SUBSCRIPTION\",\"recurrence\":\"MONTHLY\",\"nextPaymentDate\":\"2026-08-06\"}"
```

### Получение списка всех обязательств (с логикой Lazy Expiry и сортировкой):
```bash
curl -X GET http://localhost:8080/obligations
```

### Получение списка с фильтрацией (регистронезависимо):
```bash
curl -X GET "http://localhost:8080/obligations?status=active&category=subscription"
```

### Получение прогноза предстоящих расходов (по умолчанию за 7 дней):
```bash
curl -X GET "http://localhost:8080/obligations/upcoming?days=31"
```

### Зафиксировать факт оплаты обязательства по ID:
```bash
curl -X POST "http://localhost:8080/obligations/{obligation_id}/pay"
```

### Отмена активного обязательства:
```bash
curl -X PATCH "http://localhost:8080/obligations/{obligation_id}/cancel"
```

### Удаление с трансляцией реактивного SSE-события:
```bash
curl -X DELETE "http://localhost:8080/obligations/{obligation_id}"
```
